# 电击器挑战游戏实现方案

## 1. 文档信息

- 文档日期：2026-08-26
- 客户端框架：Flutter
- PC 端：Windows
- 移动端：Android、iOS
- 支持设备：电击器一代、电击器二代
- 协议依据：`电击器一代.pdf`、`电击器二代.pdf`
- 参考项目：`D:\Yokonex-dev\Yokonex-DeviceController`

## 2. 项目目标

实现一套 PC 端和移动端共用的单设备双通道电击器挑战游戏。

应用只连接一台设备，同一设备的 A、B 通道固定对应两个挑战位。无需输入挑战者名称，启动自动检测后按实际接入顺序生成“玩家1”“玩家2”等连续序号。A/B 共用一套波形、游戏时长和自动加强度规则。游戏过程中通过独立展示页查看时间、通道强度、电量和可选波形，结束后写入排行榜。

## 3. 实现边界

本项目只支持以下设备：

- 电击器一代
- 电击器二代

不包含杯杯、灌肠器、音频控制、互联网远程控制和多种设备混合控制。

第一版默认采用本地排行榜。后续需要多人共享排行榜时，再增加服务端。

## 4. 需求对应

| 编号 | 需求 | 实现方式 |
| --- | --- | --- |
| 1 | 设置游戏时长 | 开始前设置总时长，运行时自动倒计时并到时结束 |
| 2 | 自动加强度 | A、B 通道分别设置起始强度和最高强度 |
| 3 | 每 X 秒增加 N 强度 | 使用统一计算公式，保证计时误差不会累计 |
| 4 | 实时显示时间和强度 | 每张玩家卡展示已过时间、剩余时间和对应通道的设备回报强度 |
| 5 | 开始前配置波形 | 支持内置波形、自定义波形和 A/B 波形联动 |
| 6 | PC 端和移动端 | Flutter 共用业务代码，页面按窗口宽度自适应 |
| 7 | 排行榜 | 按接入顺序自动生成玩家序号，结束后保存挑战记录 |
| 8 | 达到条件判定成功 | 使用可配置的成功规则判断成功、失败或中止 |
| 10 | 开始和结束按钮 | 准备页显示开始，运行页固定显示结束和紧急停止 |
| 11 | 电量显示 | 连接后查询并监听设备电量，显示百分比和低电量提示 |
| 12 | 双通道自动擂台 | A/B 电极接入后分别自动开始，独立结算并循环等待下一名玩家 |
| 13 | 统一配置和预设 | A/B 共用一套参数，支持内置预设和本地自定义预设 |

## 5. 通道映射

应用固定创建两个挑战位：

| 挑战位 | 行为 |
| --- | --- |
| A 通道挑战者 | 只控制 A，B 的输出由 B 通道挑战者独立管理 |
| B 通道挑战者 | 只控制 B，A 的输出由 A 通道挑战者独立管理 |

### 5.1 电击器一代

一代协议通过通道号选择输出：

- `0x01`：A 通道
- `0x02`：B 通道
- `0x03`：AB 通道

应用不使用一代协议的 AB 合并控制。A、B 挑战位分别发送单通道控制包，保证两名挑战者独立计时、独立强度和独立波形。

### 5.2 电击器二代

二代协议支持 A、B 独立参数。应用将两个挑战位的实时输出合并到同一个二代控制包中，任一方结束时只把对应通道归零。

### 5.3 通道切换限制

A、B 挑战位固定，不提供运行通道切换。挑战运行中禁止修改参数，需要停止自动检测后重新配置。

### 5.4 双通道擂台

应用只支持一台设备。同一设备的 A、B 通道各对应一个挑战位，并共用统一游戏配置。配置完成后检测电极，接入后先倒计时 3 秒，确认电极仍连接后再开始放电。每次启动自动检测时序号从玩家1重新开始，后续按实际接入顺序全局递增。A/B 独立结算，任一方结束不影响另一方。

双通道擂台的一轮结束后，对应玩家卡片播放 10 秒结算动画并展示挑战结果、挑战时长和最高强度。两个挑战位都回到等待状态后自动展示排行榜。该通道必须先检测到电极断开，再次接入后才会开启下一轮，避免同一副电极连续重复开局。新一轮开始时自动返回实时展示页。

## 6. 设备协议

### 6.1 BLE 参数

| 项目 | UUID / 属性 |
| --- | --- |
| Service | `0000FF30-0000-1000-8000-00805F9B34FB` |
| 写入特征 | `0000FF31-0000-1000-8000-00805F9B34FB` |
| 写入方式 | `WRITE_WITHOUT_RESPONSE` |
| 通知特征 | `0000FF32-0000-1000-8000-00805F9B34FB` |
| 通知方式 | `NOTIFY` |

所有数据包最后一个字节都是前面所有字节的累加和低八位。

多字节数值采用高字节在前、低字节在后。

### 6.2 强度范围

协议强度范围为：

```text
0x0000：关闭
0x0001-0x00B4：强度 1-180
```

两代设备的协议硬上限统一为 180。

### 6.3 一代通道控制

```text
字节1    0x35
字节2    0x11
字节3    通道：0x01 A / 0x02 B / 0x03 AB
字节4    状态：0x00 关闭 / 0x01 开启
字节5-6  强度
字节7    固定模式 0x01-0x10 / 自定义模式 0x11
字节8    频率 1-100Hz，仅自定义模式有效
字节9    脉冲时间 0-100us，仅自定义模式有效
字节10   校验和
```

自定义模式需要约每 `100ms` 持续发送一次控制包。

### 6.4 二代固定模式

```text
字节1    0x35
字节2    0x11
字节3    0x01
字节4-5  A 通道强度
字节6    A 通道固定模式
字节7-8  B 通道强度
字节9    B 通道固定模式
字节10   校验和
```

未选择的通道强度必须写 `0x0000`。

### 6.5 二代实时模式

```text
字节1     0x35
字节2     0x11
字节3     0x02
字节4-5   A 通道强度
字节6     A 通道频率
字节7     A 通道脉冲时间
字节8-9   B 通道强度
字节10    B 通道频率
字节11    B 通道脉冲时间
字节12    校验和
```

实时模式用于游戏运行中的波形和强度变化。

### 6.6 二代频率模式

频率模式命令为 `0x03`，每次只配置一个通道：

- `0x01`：A 通道
- `0x02`：B 通道

每个数据包最多包含 100 组频率和脉冲时间。AB 使用不同波形时，需要分别发送 A、B 配置包。

第一版游戏运行优先使用实时模式。频率模式保留为波形预加载能力，经过真机验证后启用。

## 7. 电量显示

### 7.1 查询指令

主机发送：

```text
35 71 04 checksum
```

设备返回或主动上报：

```text
35 71 04 battery checksum
```

`battery` 范围为 `0x00-0x64`，对应 `0%-100%`。

### 7.2 查询时机

- 设备连接并订阅通知后立即查询。
- 进入游戏准备页时查询。
- 点击开始前查询。
- 游戏运行中每 60 秒查询。
- 收到设备主动上报时立即刷新。

### 7.3 页面状态

| 状态 | 展示 |
| --- | --- |
| 已获取 | 电量图标和百分比 |
| 低于 20% | 黄色低电量提示 |
| 未获取 | 显示“电量未知” |
| 数据过期 | 显示上次电量和“数据可能已过期” |
| 蓝牙断开 | 显示“设备已断开” |

电量查询失败不直接结束游戏，但需要记录日志并保留上一次有效数据。

## 8. 通道状态和实时强度

查询指令：

```text
35 71 01 checksum  // A 通道状态
35 71 02 checksum  // B 通道状态
```

状态响应包含：

- 电极连接状态
- 通道开启状态
- 通道强度
- 通道模式

电极连接状态：

| 值 | 含义 |
| --- | --- |
| `0x00` | 未接入 |
| `0x01` | 已接入并放电 |
| `0x02` | 已接入但未放电 |

运行页只展示当前玩家对应通道的设备回报强度，不展示游戏引擎内部目标强度。A 通道玩家卡只显示 A，B 通道玩家卡只显示 B。

设备回报强度是协议档位，不代表真实测量电流。

## 9. 游戏配置

### 9.1 基础配置

- 游戏时长
- 是否自动加强度
- 成功条件

### 9.2 通道强度配置

A/B 共用以下配置：

- 起始强度
- 最高强度
- 每隔 X 秒增加 N 强度
- 波形
- 频率范围
- 脉冲时间范围

所有输入必须满足：

```text
0 <= 起始强度 <= 最高强度 <= 180
X > 0
N > 0
```

### 9.3 强度计算

游戏运行时根据实际已过时间计算，不按定时器触发次数累加：

```text
当前强度 = min(
  最高强度,
  起始强度 + floor(已过毫秒 / 增长间隔毫秒) * 单次增长值
)
```

这样可以避免页面卡顿或系统调度延迟造成强度增长错误。

## 10. 波形配置

开始游戏前支持：

- 选择内置波形。
- 创建自定义波形。
- 编辑每段持续时间、频率和脉冲时间。
- A、B 使用同一个波形。
- 一代设备分别向 A、B 发送相同的波形参数。
- 二代设备把 A、B 的相同波形参数合并到实时控制包。

第一版内置波形包含 `Yokonex-DeviceController` 中的 16 个 EMS 经典波形，以及一套 0.5 秒一轮、频率从 14Hz 平缓提升到 20Hz 的专用波形。波形只控制频率和脉宽，强度增长始终由外部配置独立计算。

波形数据需要在开始前完成校验。无效波形不能进入游戏。

## 11. 游戏状态机

```text
idle       未配置
ready      配置完成，等待开始
countdown  开始倒计时
running    游戏运行中
stopping   正在停止并等待设备归零
success    挑战成功
failed     挑战失败
aborted    用户主动中止
error      设备或系统异常
```

主要流程：

```text
连接设备
  -> 配置 A/B 挑战位
  -> 设置挑战者和游戏参数
  -> 配置波形
  -> 开始前检查
  -> 倒计时
  -> 持续控制和实时展示
  -> 到达成功条件或游戏结束
  -> 归零并确认停止
  -> 保存结果和更新排行榜
```

双通道擂台流程：

```text
完成 A/B 参数配置
  -> 持续检测 A/B 电极状态
  -> 某通道接入后立即开始该玩家挑战
  -> A、B 分别计时、计算强度和下发波形
  -> 某通道成功、失败或手动结束
  -> 只归零该通道，另一通道继续运行
  -> 对应卡片播放本轮结果动画 10 秒
  -> 自动展示排行榜
  -> 该通道断开并重新接入后开始下一轮
```

## 12. 成功条件

第一版支持以下条件：

| 类型 | 判定方式 |
| --- | --- |
| 坚持时长 | 正常运行到游戏时长结束 |
| 达到强度 | 指定通道达到目标强度 |
| 保持强度 | 指定通道达到目标强度并保持指定秒数 |

失败条件：

- 游戏时间结束但没有达到成功条件。
- 设备断开且无法立即恢复。
- 选中的通道电极脱落。
- 控制发送异常。
- 安全限制触发。

用户点击普通结束按钮记录为“中止”，不与挑战失败混在一起。

## 13. 排行榜

排行榜不按设备协议、A/B 通道或挑战配置分组。所有记录进入同一份全场耐久榜，只按实际坚持时长从长到短排列，相同时长并列。成功、失败、中止、最高强度和结束强度不影响名次。

记录字段：

```text
id
challengerName
challengeConfigId
challengeConfigVersion
deviceProtocol
selectedChannels
result
elapsedMs
maximumStrengthA
maximumStrengthB
finalStrengthA
finalStrengthB
batteryAtStart
batteryAtEnd
startedAt
finishedAt
```

第一版使用本地数据库保存。需要联网排行榜时，客户端数据模型保持不变，只新增同步接口。

## 14. 页面设计

### 14.1 设备连接页

- 扫描设备
- 一代、二代标识
- 连接状态
- 信号强度
- 电量
- 连接和断开按钮

### 14.2 游戏准备页

- 固定展示 A、B 两个挑战位，接入后自动显示玩家序号
- A/B 统一游戏时长
- A/B 统一强度规则
- A/B 统一波形配置
- 入门、标准、进阶内置预设
- 默认选择平缓渐强预设：60 秒、起始强度 30、每秒增加 2、最高强度 180
- 保存和删除本地自定义预设
- 成功条件
- 开始按钮

### 14.3 游戏运行页

- 使用独立展示页，同时展示 A、B 两张挑战者卡片。
- 单个挑战成功或失败后，在对应卡片播放 10 秒结算动画。
- 两个挑战位均无人时切换排行榜，并自动滚动展示前 15 位；新玩家接入或点击榜单后返回游戏页。
- 按 `设备:A`、`设备:B` 管理独立挑战会话。
- 已过时间和剩余时间
- 当前挑战者
- 当前玩家对应通道的设备回报强度
- A/B 电极状态
- 当前波形
- 设备电量
- 结束按钮
- 紧急停止按钮
- 支持单独结束某名挑战者，不影响其他玩家。
- 支持全部紧急停止。
- 双通道擂台结束后在对应卡片展示挑战时长和最高强度。
- 双通道擂台结果动画持续 10 秒，两个挑战位均空闲后自动进入排行榜。

### 14.6 双视觉皮肤

应用提供两套可随时切换的游戏界面：

- 竞技计分台：明亮背景、粗边框计分卡、大号计时和荧光黄进度。
- 街机电流场：深色 HUD、实时顺位侧栏、通道强调色和系统状态区。

皮肤切换只更新页面，不重建 BLE 连接、不停止计时、不改变设备输出。应用会保存上次选择，并在下次启动时恢复。

### 14.4 结果页

- 成功、失败或中止
- 完成时间
- A/B 最高强度
- 开始和结束电量
- 查看排行榜
- 再次挑战

### 14.5 排行榜页

- 按挑战配置筛选
- 按成功状态筛选
- 展示名次、挑战者、时间、最高强度和结果
- 支持清空本地记录

## 18. 安全策略

- 开始前必须确认 BLE 已连接且通知订阅成功。
- A/B 配置缺失、波形无效或强度越界时禁止开始。
- 未启用的通道始终发送零强度。
- 正常结束、异常、断线、页面退出和应用进入后台时立即归零。
- 连续 `500ms` 没有有效控制帧时发送归零。
- 连续 `1000ms` 没有恢复时结束游戏。
- 停止失败时必须显示明确警告，提示操作设备本体。
- 协议解析必须检查包头、命令、长度和校验和。
- 强度增长只能由游戏引擎计算，页面不能绕过协议上限 180。
